### 🎯 Цель проекта
- **Решаемая проблема:** Предоставление надежного механизма для планирования локальных уведомлений и будильников по времени, которые срабатывают точно в срок, даже когда приложение свёрнуто, неактивно или полностью закрыто.
- **Важность проблемы:** ОС Android активно ограничивает фоновые процессы ради энергосбережения. Обычные фоновые потоки или таймеры завершаются при выгрузке приложения из памяти. Использование системных сервисов `AlarmManager` и `NotificationManager` гарантирует доставку уведомлений.
- **Целевая аудитория:** Пользователи, которым нужен эффективный и легкий инструмент для планирования локальных напоминаний и уведомлений.

---

### 📌 Требования к приложению

**Функциональные требования:**
1. Запуск будильника через указанное количество секунд.
2. Выбор конкретной даты (`DatePickerDialog`) и времени (`TimePickerDialog`) для установки точного будильника.
3. Мгновенная отправка и отображение системного уведомления.
4. Вызов модульного диалога выбора даты `DatePickerFragment` (`DialogFragment`).
5. Создание системного канала уведомлений и отправка уведомления с кнопками действия.

**Нефункциональные требования:**
1. **Производительность:** Минимальное потребление ОЗУ и ЦП; нулевой расход батареи в ожидании будильника (задача делегируется системному `AlarmManager`).
2. **Удобство использования (Usability):** Простой и понятный одноэкранный интерфейс с мгновенным визуальным откликом через `Toast` и `TextView`.
3. **Надёжность:** Полное соответствие современным стандартам безопасности Android:
   - Поддержка каналов уведомлений для Android 8.0+ (API 26+).
   - Безопасная установка точных будильников с проверкой `canScheduleExactAlarms()` для Android 12+ (API 31+).
   - Запрос разрешения `POST_NOTIFICATIONS` во время выполнения для Android 13+ (API 33+).
   - Защищенный `BroadcastReceiver` (`android:exported="false"`).

---

### 🧠 Общая архитектура
- **Выбранный подход:** Компонентная архитектура, управляемая событиями (Event-Driven Component Architecture: `Activity` + `Application` + `BroadcastReceiver` + `DialogFragment`).
- **Почему выбран этот подход:** Для локального приложения уведомлений прямое взаимодействие нативных компонентов с сервисами ОС (`AlarmManager`, `NotificationManager`) обеспечивает максимальную энергоэффективность, надежность и соответствие жизненному циклу Android без лишних усложнений.
- **Основные компоненты системы:**
  - `NotificationChannel` (Класс Application): Регистрирует каналы уведомлений при старте приложения.
  - `MainActivity` (UI-контроллер): Обрабатывает пользовательский ввод и разрешения.
  - `ReceiverAfterTime` (BroadcastReceiver): Перехватывает сигналы будильника и показывает уведомления.
  - `DatePickerFragment` (DialogFragment): Модульный фрагмент для выбора даты.

### 🧩 Подробное описание классов

**📌 Класс: NotificationChannel**
- **Роль:** Наследник `android.app.Application`.
- **Зона ответственности:** Инициализация приложения при запуске. Регистрирует каналы уведомлений в системе Android (`NotificationManager`) на устройствах с Android 8.0 (API 26) и выше.
- **Основные методы:**
  - `onCreate()` — Точка входа при старте процесса приложения.
  - `createNotificationChannels()` — Настраивает ID канала (`CHANNEL_1_ID`), имя, уровень важности (`IMPORTANCE_HIGH`) и описание.
- **Взаимодействие:** Предоставляет статическую константу `CHANNEL_1_ID`, используемую в `ReceiverAfterTime`.

**📌 Класс: MainActivity**
- **Роль:** Главная Activity (`AppCompatActivity`).
- **Зона ответственности:** Связывание элементов UI (через `findViewById`), обработка кликов, валидация ввода, запрос разрешений и планирование будильников в `AlarmManager`.
- **Основные методы:**
  - `onCreate()` — Инициализирует макет, экземпляр `Calendar`, слушатели и проверяет разрешения.
  - `initElements()` — Поиск представлений через `findViewById()`.
  - `checkPermissions()` — Запрос разрешения `POST_NOTIFICATIONS` на Android 13+.
  - `scheduleAlarmAfterSeconds()` — Чтение текста, валидация и установка отложенного будильника.
  - `choiceDate()` — Открытие `DatePickerDialog` с ограничениями min/max без изменения базового календаря.
  - `choiceTime()` — Открытие `TimePickerDialog` (с `Calendar.HOUR_OF_DAY`) и обновление `tvWhere`.
  - `scheduleSelectedAlarm()` — Установка точного будильника на выбранную дату и время.
  - `triggerImmediateNotification()` — Мгновенный вызов уведомления.
  - `setExactAlarm()` — Безопасный метод установки будильника с учётом правил Android 12+.

**📌 Класс: ReceiverAfterTime**
- **Роль:** Системный приемник широковещательных сообщений (`android.content.BroadcastReceiver`).
- **Зона ответственности:** Перехватывает интенты от `AlarmManager` при срабатывании времени и отображает системное уведомление.
- **Основные методы:**
  - `onReceive()` — Вызывается системой при наступлении времени будильника.
  - `buildAndShowNotification()` — Создает уведомление через `NotificationCompat.Builder` с `PendingIntent` и передает его в `NotificationManager`.

**📌 Класс: DatePickerFragment**
- **Роль:** Диалоговый фрагмент (`androidx.fragment.app.DialogFragment`).
- **Зона ответственности:** Переиспользуемый компонент для выбора даты через системный диалог.
- **Основные методы:**
  - `onCreateDialog()` — Создает `DatePickerDialog` с текущей датой.
  - `onDateSet()` — Обработчик выбора даты.

### ⚙️ Работа с потоками
- **Главный поток (UI Thread):** Вся работа с интерфейсом, показ диалогов и обновление текста выполняются в главном потоке.
- **Фоновые операции:** Отсчет времени выполняется ядром ОС Android через `AlarmManager`. Приложению не требуется висеть в памяти.
- **Предотвращение ANR и утечек памяти:**
  - В UI-потоке отсутствуют блокирующие операции.
  - Отсутствуют статические ссылки на `Activity`.
  - `PendingIntent` использует `FLAG_IMMUTABLE`.

---

### 💾 Работа с данными
- **Хранение данных:** Состояние в памяти в объекте `Calendar` во время работы Activity.
- **Причина выбора:** Для разовой установки будильника не требуется постоянное хранилище.
- **Целостность данных:** Объект `Calendar` клонируется при расчёте ограничений даты (`setMaxDate`), чтобы избежать искажения времени.

---

### 🌐 Работа с сетью
- Приложение работает 100% локально и автономно. Сетевые разрешения не требуются.

---

### 🔐 Безопасность
- **Ограничение экспорта:** `ReceiverAfterTime` объявлен с `android:exported="false"`, что защищает от вызова сторонними приложениями.
- **Безопасность PendingIntent:** Флаг `PendingIntent.FLAG_IMMUTABLE` защищает интент от модификации.
- **Минимальные разрешения:** Запрашиваются только строго необходимые разрешения (`POST_NOTIFICATIONS`, `USE_EXACT_ALARM`, `SCHEDULE_EXACT_ALARM`).

- Динамическая проверка разрешений перед отправкой уведомлений.
- Безопасный вызов точных будильников через `canScheduleExactAlarms()` на API 31+.
